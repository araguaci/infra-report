# Infra Report — visualização local e túnel SSH

Guia para gerar e abrir `infra-report.html` **sem expor** o relatório na internet.

> **Proibido:** publicar em `docs.orbitall.app`, Caddy público, Portainer ou qualquer URL externa. O relatório contém achados de segurança (portas, SSH, containers).

## Arquivos

| Arquivo | Função |
|---------|--------|
| `/root/analisar-infra.sh` | Auditoria (portas, firewall, SSH, HTTP/S, Docker, hardening) |
| `/root/infra_report_render.py` | Monta JSON + HTML a partir da coleta |
| `/tmp/infra-report.json` | Dados (padrão ao rodar com `--json`) |
| `/tmp/infra-report.html` | Página web do relatório |

## 1. Gerar o relatório

No servidor:

```bash
sudo bash /root/analisar-infra.sh --json /tmp/infra-report.json
```

Saídas:

- `/tmp/infra-report.json`
- `/tmp/infra-report.html` (mesmo basename, extensão `.html`)

Opções úteis:

```bash
# HTML em outro caminho
sudo bash /root/analisar-infra.sh --json /tmp/infra-report.json --html /tmp/meu-relatorio.html

# Incluir probes HTTP/HTTPS em um domínio
sudo bash /root/analisar-infra.sh --json /tmp/infra-report.json --host orbitall.app
```

## 2. Abrir `infra-report.html` (recomendado: túnel SSH)

### Por que túnel?

A porta `8765` (ou qualquer porta alta) costuma ser **bloqueada no firewall da Hostinger**, mesmo com o serviço escutando no VPS. Além disso, servir o relatório em `0.0.0.0` expõe dados sensíveis.

O túnel faz o browser acessar **apenas localhost** na sua máquina, encaminhando o tráfego pela sessão SSH já autenticada.

### No seu computador (cliente)

Substitua usuário/IP se necessário (`2.25.92.168` é o IP deste VPS):

```bash
ssh -N -L 8765:127.0.0.1:8765 root@2.25.92.168
```

Deixe esse terminal aberto. Em outro terminal **no servidor**, suba o HTTP **só em loopback**:

```bash
cd /tmp
python3 -m http.server 8765 --bind 127.0.0.1
```

No browser da sua máquina:

**http://127.0.0.1:8765/infra-report.html**

### Flags do SSH

| Flag | Significado |
|------|-------------|
| `-L 8765:127.0.0.1:8765` | Encaminha a porta local `8765` para `127.0.0.1:8765` no VPS |
| `-N` | Não abre shell remoto (só o túnel) |
| `-f` | (opcional) sobe o túnel em background |

Exemplo em background:

```bash
ssh -f -N -L 8765:127.0.0.1:8765 root@2.25.92.168
```

Para encerrar o túnel em background:

```bash
# Linux/macOS — achar o processo e matar
ps aux | grep '8765:127.0.0.1:8765'
kill <PID>
```

### Windows (PowerShell / OpenSSH)

```powershell
ssh -N -L 8765:127.0.0.1:8765 root@2.25.92.168
```

Depois abra no browser: `http://127.0.0.1:8765/infra-report.html`

### Windows (PuTTY)

1. Session → Host: `2.25.92.168`
2. Connection → SSH → Tunnels
3. Source port: `8765`
4. Destination: `127.0.0.1:8765`
5. Local / Auto → Add → Open da sessão
6. No VPS: `python3 -m http.server 8765 --bind 127.0.0.1` em `/tmp`
7. Browser: `http://127.0.0.1:8765/infra-report.html`

## 3. Alternativa sem HTTP server

Se já tiver o HTML no servidor, copie para a máquina local:

```bash
scp root@2.25.92.168:/tmp/infra-report.html ./infra-report.html
scp root@2.25.92.168:/tmp/infra-report.json ./infra-report.json
```

Abra o `.html` no browser (duplo clique). O JSON já vem embutido na página; o botão **Carregar JSON** serve para trocar o relatório sem regerar o HTML.

## 4. Uso da página

- **Score / contadores** — postura geral (crítico, aviso, info, ok)
- **Achados** — filtros por severidade
- **Recomendações** — ações priorizadas
- **Portas / SSH / Firewall / HTTP / TLS / Docker** — detalhes da coleta
- **Baixar JSON embutido** — exporta o payload da página
- **Imprimir / PDF** — via diálogo de impressão do browser

## 5. Checklist de segurança

- [ ] Não copiar para `/var/www/lorentz-docs` nem qualquer root do Caddy público
- [ ] Sempre usar `--bind 127.0.0.1` no `http.server`
- [ ] Não liberar a porta `8765` no firewall da Hostinger só para ver o relatório
- [ ] Encerrar o `python3 -m http.server` ao terminar
- [ ] Tratar JSON/HTML como informação confidencial

## 6. Troubleshooting

| Sintoma | Causa provável | Ação |
|---------|----------------|------|
| `ERR_CONNECTION_TIMED_OUT` em `http://IP:8765` | Firewall do provedor ou bind em `0.0.0.0` bloqueado externamente | Use túnel SSH + `--bind 127.0.0.1` |
| Página em branco / score "—" | JSON embutido inválido ou arquivo antigo | Regenere com `analisar-infra.sh --json ...` |
| `Connection refused` no túnel | HTTP server não está rodando no VPS | No servidor: `ss -tlnp \| grep 8765` e suba o `http.server` |
| Porta já em uso | Outro processo em `8765` | `pkill -f 'http.server 8765'` ou use outra porta nos dois lados (`-L 8770:127.0.0.1:8770`) |

## 7. Fluxo rápido (copiar e colar)

**Servidor:**

```bash
sudo bash /root/analisar-infra.sh --json /tmp/infra-report.json
cd /tmp && python3 -m http.server 8765 --bind 127.0.0.1
```

**Seu PC:**

```bash
ssh -N -L 8765:127.0.0.1:8765 root@2.25.92.168
```

**Browser:** [http://127.0.0.1:8765/infra-report.html](http://127.0.0.1:8765/infra-report.html)
